# GPS Integrity Monitoring System

End-to-end real-time GPS integrity monitoring stack for ESP32, NEO-6M GPS, MPU6050, Python ML inference, and a mission-control React dashboard.

## What It Includes

- ESP32 Arduino firmware reading GPS, GPGSV satellite data, MPU6050 motion, and driving green/red integrity LEDs.
- FastAPI backend with `/data`, `/latest`, `/health`, `/alerts/export`, and `/ws`.
- Isolation Forest training pipeline using synthetic normal, spoofing, jamming, satellite-drop, HDOP-spike, and sensor-inconsistency examples.
- React dashboard with KPI cards, charts, alert feed, satellite sky plot, 3D Earth/orbit view, and system health.
- WebSocket live updates with API polling fallback.

## Hardware Connections

| Module | ESP32 Pin |
| --- | --- |
| NEO-6M VCC | 3.3V or 5V, depending on board regulator |
| NEO-6M GND | GND |
| NEO-6M TX | GPIO 16 |
| NEO-6M RX | GPIO 17 |
| MPU6050 VCC | 3.3V |
| MPU6050 GND | GND |
| MPU6050 SDA | GPIO 21 |
| MPU6050 SCL | GPIO 22 |
| Green LED anode | GPIO 25 through 220 ohm resistor |
| Red LED anode | GPIO 26 through 220 ohm resistor |
| LED cathodes | GND |

## ESP32 Firmware Setup

1. Open `esp32/main.ino` in Arduino IDE.
2. Install libraries from Arduino Library Manager:
   - `TinyGPSPlus`
   - `ArduinoJson`
   - `Adafruit MPU6050`
   - `Adafruit Unified Sensor`
3. Update these constants:

```cpp
const char *WIFI_SSID = "YOUR_WIFI_SSID";
const char *WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";
const char *BACKEND_URL = "http://YOUR_COMPUTER_IP:8000/data";
```

4. Select your ESP32 board and port.
5. Flash the sketch.

The firmware sends telemetry once per second. If GPS is unavailable, it enters simulation mode and still exercises the full pipeline.

## Backend Setup

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python train_model.py
uvicorn server:app --host 0.0.0.0 --port 8000
```

Useful endpoints:

- `POST http://localhost:8000/data`
- `GET http://localhost:8000/latest`
- `GET http://localhost:8000/health`
- `GET http://localhost:8000/alerts/export`
- `ws://localhost:8000/ws`

## LED Logic

- `NORMAL`: green LED on, red LED off.
- `ANOMALY`: red LED on, green LED off.
- Backend unreachable: firmware treats it as anomaly for fail-safe indication.

## ML Features

The model receives:

```text
[hdop, sat_count, lat, lon, ax, ay, az, gx, gy, gz]
```

Detection combines Isolation Forest output with integrity guardrails:

- GPS fix loss
- HDOP spike
- satellite count collapse
- high gyro motion inconsistency

## Troubleshooting

- Dashboard shows `LINK OFFLINE`: confirm `uvicorn` is running on port `8000` and browser can reach `/latest`.
- ESP32 gets no response: set `BACKEND_URL` to your computer LAN IP, not `localhost`.
- GPS has no fix indoors: move the antenna near a window or use simulation mode until a fix is acquired.
- MPU6050 not detected: check SDA/SCL wiring and power level.
- CORS/browser issues: backend already allows all origins for lab deployment.
- `model.pkl` missing: run `python train_model.py`, or just start the backend and it will train automatically.

## Notes

This is a lab-grade integrity monitor suitable for research, demonstrations, and prototyping. For flight-critical or safety-certified navigation, add authenticated GNSS checks, receiver-specific raw measurements, disciplined timing, persistent storage, formal validation, and certification-grade fault trees.
